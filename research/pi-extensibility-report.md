# THE RECOMMENDATION

- Install pi-subagents, pi-intercom, @gotgenes/pi-permission-system, @juicesharp/rpiv-advisor, and @juicesharp/rpiv-workflow as the orchestration substrate, define every specialist and phase body as a markdown file under .pi/agents/ and .pi/skills/ with source-reviewed rpiv-workflow packs sequencing them through fs-existence stage validators fed by tool-call and workspace-diff collectors, copy gentle-pi's two-file judgment-day skill with its interactive gates rewritten for unattended stage use plus rpiv-pi's three standalone verifier agents as frontmatter-normalized git-tracked file-add specialists dispatched by subagent-authorized judge children over marker-gated setup-hook-seeded worktrees under an explicitly enumerated extension-tool permission base, and build only goose-style deterministic check scripts with timeoutMs caps, a PID-aware run-lock-and-resolution preflight with a transcript-tail-and-wall-clock stall watchdog, and one compose-review-publish landing pipeline that advances main via an ff-only merge to a recorded composed-commit target SHA only after every check and review passes on the committed integration tree, because rpiv-workflow already persists resumable per-run JSONL state — a design that explicitly trades away the EXTENSIBLE definition's file-add grain for phases, since inserting a phase into an existing workflow edits that workflow's pack file rather than adding a file.
